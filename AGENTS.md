# Rules for AI coding agents (opencode, Claude, Copilot, Cursor, …)

Read this before changing anything. These rules exist because an agent once committed private settings
and changed the public data format, which broke the website.

## Never
- Never commit or push `data/`, `logs/`, `inbox/`, `settings.json`, `*.db`, `.venv*`, `.tools/`.
  They hold the owner's name, email, telescope location, Discord webhooks and GitHub token.
- Never put a real email, webhook URL, token, API key, home-folder path (`/Users/...`) or coordinates in code, docs or tests.
  Use `example.com` addresses and made-up numbers in tests.
- Never force-push, rebase or rewrite `main`. Never delete branches.
- Never push to `gh-pages` by hand. It is generated by `spacelab/publish.py` from the owner's data.
- Never edit files under `data/public/` to "fix" the website. Fix the code that builds it.
- Never disable or edit `.githooks/`, `.github/workflows/`, the privacy scan (`publish.scan`, `publish.forbidden`)
  or the schema check (`publish.validate`).
- Never open the owner's live database (`data/spacelab.db`) for writing from outside the app.

## Fun / learning features for the public page
Build them in `web/extras.js` and `web/extras.css` only, following [EXTRAS.md](EXTRAS.md). Pick tasks from
[ROADMAP.md](ROADMAP.md) in order, one task per branch.

## The public data format
`web/public.js` reads `data.json`, built by `publish.build_data`. Its shape is fixed by `publish.SCHEMA`.
If you need to change it: change `build_data`, `SCHEMA`, `SCHEMA_VERSION` and `public.js` in the same commit,
and keep old keys working. `publish.validate` refuses to publish data that does not match.

## Before every commit
```
python tests/test_offline.py
node --check web/app.js
node --check web/public.js
```
All tests must pass. Add a test for anything new. Tests run with a temporary data folder (`SPACELAB_DATA`).

## How to contribute changes
Work on a branch, open a pull request, and let the owner review it. Keep changes small and explain them in plain English.
